## 9. Gate D borrow observations and event rules

### 9.1 Formation observation

Exactly one `formation_borrow_observation` is required per prospective short at formation cutoff. Its composite key is:

```text
(package_id, security_id, security_id_namespace, exchange_calendar_id,
 formation_session_id, active_session_id, record_type)
```

It contains availability-as-of, observed time, effective start/end, borrow availability, daily fee, threshold, available quantity, required quantity, and `quantity_sufficient`.

Required invariants:

```text
observation_timestamp_utc <= formation_cutoff_timestamp_utc
availability_as_of_timestamp_utc <= formation_cutoff_timestamp_utc
effective_start <= formation_cutoff < effective_end
borrow_available = true
bps_per_day is finite and >= 0
bps_per_day <= fee_threshold_bps_per_day
available_borrow_quantity >= required_borrow_quantity
quantity_sufficient = true
```

### 9.2 Daily active-session observation

Exactly one `active_session_borrow_observation` is required for every active short/security/session before regular open. Its composite key adds `trade_date` and `active_session_id`. No prior-day record may satisfy it.

Required invariants:

```text
pre_session_cutoff <= regular_session_open
observation_timestamp <= pre_session_cutoff
availability_as_of <= pre_session_cutoff
effective_start <= pre_session_cutoff < effective_end
borrow_available = true
finite non-negative bps_per_day
bps_per_day <= fee_threshold_bps_per_day
available_borrow_quantity >= required_borrow_quantity
quantity_sufficient = true
```

### 9.3 In-session event

An `in_session_borrow_event` is zero-or-more per active short/security/session. Its key includes package, security identity, calendar/session identities, trade date, and event ID.

Required event order:

```text
event_effective_timestamp_utc <= event_observed_timestamp_utc
availability_as_of_timestamp_utc <= event_observed_timestamp_utc
regular_session_open <= event_observed_timestamp < regular_session_close
event effective window covers event_effective_timestamp
```

When `borrow_available_after_event = true`, fee, threshold, available quantity, and boolean threshold/quantity conclusions are non-null and finite as applicable. When it is false, those post-event fields are all null. Null fields for a loss event do not prohibit an audited exit.

Events order deterministically by observed timestamp ascending, effective timestamp ascending, priority descending, source record ID ascending, and lineage hash ascending. Same-observed-time, same-priority materially contradictory events, or contradictory overlapping effective windows, block.

No event may cause an exit before it is observable. An event observed at or after close, or whose first executable exit is at or after close, fails with:

```text
BLOCK_AFTER_CLOSE_OR_NONEXECUTABLE_EVENT
```

### 9.4 Post-event action

The continuing exposure horizon is:

```text
[event_observed_timestamp_utc, regular_session_close_timestamp_utc)
```

```text
CONTINUE iff borrow remains available, fee and quantity evidence are valid,
threshold_result == (bps <= threshold),
quantity_sufficient == (available >= required), both results are true,
and the effective window covers the entire continuing horizon.

EXIT iff the event is observable before close and either borrow is unavailable,
or valid post-event threshold/quantity evidence fails, and complete same-session
forced-exit evidence exists.

BLOCK otherwise.
```

For EXIT, the causal chain is mandatory:

```text
event_observed_timestamp_utc
<= exit_order_submission_timestamp_utc
<= first_eligible_execution_timestamp_utc
= exit_execution_timestamp_utc
< regular_session_close_timestamp_utc
```

The loss-event accrual rate is pinned exactly to the accepted same-session daily active-borrow observation:

```text
loss_event_accrual_source_record_id
  = accepted_active_session_borrow_observation.source_record_id
loss_event_accrual_bps_per_day
  = accepted_active_session_borrow_observation.bps_per_day
```

It must be finite, non-negative, and resolve to exactly one same-security, same-active-session, same-required-quantity accepted observation. It is not selected from an alternate record or inferred from post-event fee fields.

## 11. Existing active-short pre-open failure

A missing or failed daily active-session observation for an existing short before regular open requires either audited `pre_open_exit_evidence` or session block.

Pre-open evidence requires:

```text
failure_observed_timestamp_utc < regular_session_open_timestamp_utc
failure_observed_timestamp <= exit_order_submission <= exit_execution
regular_session_open <= exit_execution < regular_session_close
exit_execution = first eligible execution under frozen policy/replay proof
price_reference_type = prior_regular_session_close
```

Prior-session borrow accrual ends at prior regular close. Current-session pre-open-exit accrual begins at current regular open:

```text
current accrual interval = [regular_session_open, exit_execution)
```

An exact-open exit has zero current-session fraction and may have a null rate/source. For an exit after open, an independently anchored authoritative pre-open exit rate is required, available as of order submission, effective across `[open, execution)`, and unit-compatible with the declared exchange-session-fraction accrual convention.

```text
borrow_accrual_fraction =
(exit_execution - regular_session_open) /
(regular_session_close - regular_session_open)

borrow_cost_through_exit =
abs(short_weight_at_price_reference)
* pre_open_exit_accrual_bps_per_day
* borrow_accrual_fraction / 10000
```

The short return is always calculated through the negative short weight:

```text
underlying_return = (exit_price - price_reference_price) / price_reference_price
short_leg_return = short_weight_at_price_reference * underlying_return
```

After a valid pre-open exit, apply deterministic post-exit composition. Block if minimum short-leg count, dollar neutrality, gross/net, concentration, or any declared constraint fails. Never preserve a long-only residual.

## 12. Daily cost and post-exclusion composition

For continuing shorts:

```text
continuing_short_cost_t =
Σ(abs(short_weight_i,t) * bps_per_day_i,t / 10000)
```

A full regular exchange session is one daily accrual unit. For audited exits:

```text
forced_exit_borrow_cost_j =
abs(short_weight_at_price_reference_j)
* loss_event_accrual_bps_per_day_j
* borrow_accrual_fraction_j / 10000

total_borrow_cost_t =
Σ continuing_short_cost_i + Σ forced_exit_borrow_cost_j
```

An exited security must not receive both normal continuing cost and forced-exit borrow cost. Exit return and transaction cost apply once only.

For a failed pre-formation short:

```text
exclude only the affected short candidate
make no lower-ranked replacement
construct only from remaining original candidates
re-freeze and revalidate all surviving short quantities if shares change
block if any short-leg, neutrality, gross, net, concentration, or declared
exposure constraint cannot be satisfied
```
